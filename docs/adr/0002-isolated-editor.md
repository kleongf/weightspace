# The Editor runs isolated, never in this repo

A Claude session working inside this repo can read the Held-out set and the scorer's source, which would quietly break every result. So each Run starts a separate headless Claude Code session (`claude -p`, on the user's subscription, no API key) in a throwaway folder outside the repo, with every built-in tool switched off (`--tools ""`) and exactly two tools served by a local MCP server (`--strict-mcp-config`): a persistent Python sandbox and `evaluate`. As in the original paper, the sandbox holds the Target's weights as arrays the Editor reads and edits in place. When a Patch is saved, the harness diffs the arrays against the Baseline into a sparse list of changed weights. The Held-out set never enters the run folder, and the harness ships with a test that proves it. The cost is extra plumbing, plus the loss of the interactive Code tab as the Editor, which was the original plan.
